一、角色与职责边界

这是整个产品的骨架：制度口径由乔姐说了算，业务事实由周敏说了算，助手只做检索和呈现，不越界。

角色人负责什么在小程序里能做什么
员工 全体员工 — 自助查现行有效制度；向助手提问；经授权后查本人单据进度
行政专员 乔姐 制度口径：制定、改版、停用 制度维护台：新增制度、发布新版、设定生效日期、停用旧版、编辑条款与检索关键词
财务专员 周敏 业务事实：金额、事由、凭证 业务事实核对台：待核对队列、四项核对要点、核对结论、驳回、标记已打款

三条不可逾越的界线

  • 助手不改制度口径。它只检索乔姐维护的现行有效版本；已失效版本不参与作答。
  • 助手不认定业务事实。单据的金额、事由、凭证以周敏的核对结论为准，页面上明确标注是否已核对。
  • 只能看自己的单据。员工按单据 id 直接访问他人单据会被拒绝；只有财务专员（核对业务事实）可读取全部。

二、一期：员工自助查有效制度

制度库

  • 默认只显示现行有效版本（状态为生效中，且今天在生效日与失效日之间）。
  • 按分类筛选、按名称或条款关键词搜索；可手动打开开关查看已失效历史留档。
  • 失效版本带「已失效」标记与页面警示，明确不能作为报销依据。

制度详情

  • 展示条款正文（编号 + 标题 + 内容）、版本号、生效/失效日期、维护人（乔姐）、最近更新、修订说明。
  • 末尾说明口径责任归属，并可直接就这条制度发起提问。

制度问答

  • 一句话提问 → 检索现行制度条款 → 给出条款原文 + 出处卡片（制度名 / 编号 / 版本 / 生效日期 / 条款号 / 维护人）。
  • 命中多条相关条款时一并给出；点卡片可直接跳到制度原文核对。
  • 检索不到就明说，不套用失效版本、不推测，并引导去找乔姐确认口径。
  • 问答留痕只存在本人名下，可回看、可清空。

乔姐的制度维护台

  • 新增制度；编辑条款（条款号、标题、正文、检索关键词）；设定分类、版本、生效/失效日期、状态。
  • 「发布新版」：复制现行版本生成新版本，保存后旧版本自动转为已失效并留档，员工问答立刻只采用新版。
  • 停用制度；停用后该制度不再作为报销依据，也不再参与问答。
  • 非行政专员进入会被拒，并提示联系乔姐。

三、二期：经授权查询本人单据

授权先行

第一次进入单据页会弹出授权说明，逐条列明「需要读取什么」和「不会做什么」，同意后才展示单据；可在「我的」中随时撤回。授权范围严格限定为本人名下单据及其流转记录。

我的单据

  • 列表显示单据编号、费用类型、金额、事由、状态、提交时间，以及业务事实是否已经周敏核对。
  • 筛选「全部 / 在办 / 已完成」；财务专员额外有「待核对」筛选并显示提交人信息。
  • 刚上手可以「载入示例单据」，直接体验完整流程。

单据详情

  • 金额、状态与状态说明；完整流转时间轴（提交申请 → 部门审核 → 财务核对 → 审核通过 → 已打款），未完成的节点以灰色待办显示。
  • 业务事实核对卡：已核对的显示核对人与核对意见；未核对的明确写「以周敏的核对结论为准，核对完成前金额与状态仅供参考」。
  • 单据信息（单号可复制、类型、金额、提交人、提交时间、事由）。
  • 自动关联适用制度（按费用类型匹配），一键跳到现行有效原文。

周敏的业务事实核对台

  • 待核对队列 / 待打款 / 全部单据三个视图，带数量统计。
  • 核对弹层里同时给出制度参考（乔姐维护的对应制度摘要，可点开原文）——制度口径与业务事实在这里对照。
  • 四项核对要点逐项确认：金额与发票一致无涂改、事由与实际业务相符、未超制度上限、凭证材料齐全。
  • 填写核对意见 →「核对通过」推进为已通过；「驳回」必须写具体原因，员工在单据详情能看到。
  • 已通过的单据可「标记已打款」，状态变为已打款并记录流转。
