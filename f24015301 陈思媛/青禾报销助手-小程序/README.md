# 青禾报销助手

微信原生小程序。解决一个很具体的问题：**员工问「住宿一晚能报多少」，不该靠翻群聊记录或者问同事。**

一期让员工自助查到**现行有效**的制度口径；二期在授权前提下，让员工查到**本人**单据的进度。

## 关键设计：谁负责什么

这个项目的重点不在 UI，而在把三方的职责边界落进**权限层**，而不是只写在文案里。

| 角色 | 是谁 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| 员工 | 全体员工 | 查现行有效制度、一句话提问、经授权查**本人**单据 | 查不到别人的单据；不能替财务认定业务事实 |
| 行政专员 | 乔姐 | 新增制度、**发布新版**、设定生效日期、停用旧版 | 不能修改单据的业务事实认定 |
| 财务专员 | 周敏 | 核对单据业务事实（金额 / 事由 / 凭证）、驳回、标记已打款 | 不能修改制度口径 |

三条硬边界，代码里有对应的拦截，不只是提示语：

1. **口径只认现行有效版本。** 检索引擎只喂现行有效的条款给问答，已失效的历史版本不参与作答。问「住宿费每晚上限是 400 元吗」这类问题，助手会答 v3.2 的分档标准（500 / 400 / 300），不会被旧口径带偏。
2. **单据仅本人可见。** 拿别人的单据 id 直接访问会被拒绝；财务/行政专员因核对需要可读全部。
3. **检索不到就明说。** 现行制度没覆盖的问题，助手不套用失效版本、不做推测，直接引导去找乔姐确认口径。

## 功能

**一期 · 制度自助查询**

- 制度库默认只显示现行有效版本，失效版需手动打开开关，并带失效警示
- 一句话提问 → 命中条款 + 出处卡片（制度名 / 编号 / 版本 / 生效日期 / 条款号 / 维护人），点卡片跳原文
- 问答留痕只存在本人名下，可回看、可清空
- 乔姐的制度维护台：改版走「发布新版」，新版生效后旧版自动转已失效并留档

**二期 · 经授权查本人单据**

- 首次进入「单据」弹授权说明（需要读什么 / 不会做什么），同意后才展示，可在「我的」随时撤回
- 单据详情：完整流转时间轴 + **业务事实核对卡**（已核对显示周敏的核对人与意见；未核对明确标注「以周敏核对结论为准，此前金额仅供参考」）
- 自动关联适用制度，一键跳现行有效原文
- 周敏的核对台：待核对队列、四项核对要点、核对意见、驳回、标记已打款；核对页同时给出对应制度条款作对照

## 目录结构

```
.
├── app.js / app.json / app.wxss      # 小程序入口、页面注册、全局样式
├── project.config.json               # 开发者工具项目配置（AppID 为测试号）
├── pages/
│   ├── index/                        # 首页：能力入口 + 热门问题 + 口径责任
│   ├── policy/                       # 制度库：分类筛选、搜索、含失效开关
│   ├── policy-detail/                # 制度详情：元信息 + 条款 + 修订说明
│   ├── ask/                          # 制度问答：对话式，带条款出处
│   ├── docs/                         # 我的单据：授权弹层 + 状态筛选
│   ├── doc-detail/                   # 单据详情：流转时间轴 + 业务事实核对卡
│   ├── admin/                        # 乔姐：制度维护台
│   ├── finance/                      # 周敏：业务事实核对台
│   └── me/                           # 我的：身份、授权、数据管理
└── utils/
    ├── dict.js                       # 角色 / 状态 / 分类等字典
    ├── seed.js                       # 演示制度库与单据数据
    ├── store.js                      # 数据层 + 本地权限规则（对应云端 RLS）
    ├── retrieve.js                   # 条款检索引擎（仅检索现行有效制度）
    └── format.js                     # 日期 / 金额格式化
```

## 运行

1. 打开**微信开发者工具** → 导入项目 → 选择本目录
2. AppID 填**测试号**（项目里的 `touristappid` 即测试号，不需要自己的 AppID）
3. 编译即可运行

体验三种角色：进入「我的」→「体验身份」一键切换。也可以用「编辑」填工号自动匹配角色：

- `QG-0001` → 自动绑定为行政专员（乔姐）
- `CW-0001` → 自动绑定为财务专员（周敏）
- 其他合法工号（如 `ZH-1024`）→ 普通员工

## 数据说明

当前是**本地体验模式**：身份、制度、单据、问答留痕都保存在本机本地存储，`utils/store.js` 用一个统一读写接口承载，并在本地实现与云端 RLS 完全对应的权限规则。

`utils/seed.js` 里内置 5 部现行制度 + 1 部失效版，是演示用的示例口径，**不是任何公司的真实制度**。接入实际使用前需要替换为真实制度内容。

接云服务时只需把 `utils/store.js` 的方法体替换为等价的云端数据库查询，页面代码无需改动。
